Hard rule, enforced globally, not per-component: the prototype's stylesheet opens with *{border-radius:0!important}. Every button, card, input and tile in the markup still carries an inline border-radius (4px, 6px, 8px, 50%) for portability, but the system stamps it flat everywhere at once. Build components with whatever radius is convenient to reuse — enforce zero at the theme layer, the same way this prototype does, rather than hand-zeroing every component.

The prototype's own chrome is not app UI. The #EFEEEB mat behind the device frame, the Mobile/Desktop/Reset control bar, and the fake iOS status bar (09:41 · GRAINS) exist only to demo the prototype inside itself — they are not part of Grains' shipped interface and carry no token status. The real app background is --paper.

Accent is a single token, not a theme. The prototype exposes --signal as a swappable prop for design review (red / ink / blue / teal were all wired up) — but the shipped default, and the only one visual-identity.html sanctions, is signal red #E23B22. Treat the swap capability as a review tool, not evidence that Grains supports accent theming.

Bilingual pattern

data-lang toggle

A single app-level data-lang="en"|"th" attribute drives visibility for every bilingual pair via [data-l="en"] / [data-l="th"] spans — nothing is duplicated per-component. The leading language always gets the larger, higher-confidence treatment (serif at weight 500 for EN, Noto Sans Thai at weight 600 for TH); the trailing language sits directly beneath in ash, in the *other* family — English glossing Thai in Fraunces italic-adjacent serif, Thai glossing English the same way in reverse. Neither is ever the "small print" version of the other.

Layout & responsive frame

2 breakpoints, no fluid middle

The prototype models exactly two device states — there is no tablet-intermediate layout. Mobile is a single 390px column; desktop is a 1280px frame that opens a second column (map, filter rail, or metadata sidebar) alongside the primary content. Screens either fully restructure between the two (discovery, lab detail, stock detail) or stay identical (entry, auth).

Components

built from the tokens above

Buttons

One filled signal button per screen, at most — reserved for the single highest-commitment action (Publish lab, Save, Add the first lab). Everything else is an ink outline or a plain underlined link.

Filter chips — process-coded

Border always carries the process color, selected or not. Scanner/equipment chips reuse the exact same data-on mechanic but stay plain ink — equipment isn't chemistry.

Status pill

Deliberately achromatic. Status is not a process and never borrows the process key or the signal color — solid vs. italic vs. faded carries all three states.

Open now Temporarily closed Closed

Badge

Fixed roster (Clean Scan, Fast Turnaround, Accurate Colors, Good for Beginners), always shown with a live count. A zero-count badge stays visible, dashed — an invitation. Tapping to endorse fills it solid; endorsing is gated behind sign-in, one endorsement per person.

Service checklist

Three states, not two — a service can be offered, explicitly not offered, or simply never recorded. "Unknown" is its own faint, unchecked-but-not-negated state, distinct from "no."

Map pin

A rotated square with one squared-off corner (border-radius:50% 50% 50% 0 pre-flattening) — the classic teardrop map marker. The viewer's own position is a plain solid dot, deliberately not pin-shaped, so it never reads as a lab.

Inputs — two weights

Primary fields (name, landmark, area search) get a heavy 2px ink border at 14px type — they're the ones a contributor fills once. Dense data-grid cells (per-process pricing table, seven-row hours grid, contact list) drop to a lighter 1.5px hairline border at 12–13px, because the input is the table cell — the shape of the data is the shape of the field, not a freeform box.

Toast

Fixed bottom-center, ink-filled, slides up + fades in over .22s, auto-dismisses after 3.6s. Reserved for confirming a just-completed write ("3 fields live now — no review queue.") — never for errors or blocking validation.

Empty state

Consistent three-part shape everywhere it appears (no labs in an area, no film stock matches, no gallery samples yet): a dashed icon, a Fraunces headline, ash body copy — then a signal-filled primary action paired with a lighter secondary escape hatch.

Interaction rules

behavior, not just pixels

Auth is deferred and contextual

Every write action (edit, publish, endorse, revert) routes through one auth(reason, then) gate that shows a specific, honest reason ("Endorsing a badge needs an account — one endorsement per person") before Google sign-in — never a generic wall, never on page load. Browsing is always fully open.

No review queue

Every save is described in its own confirmation copy as live immediately ("goes live now", "no review queue") and attributed to the editor. Trust comes from the edit-history log being complete and revertible, not from pre-publication moderation.

A revert is an edit

Reverting a change creates a new history entry rather than erasing the old one — the diff row pattern is reused, not special-cased, and the revert itself requires the same sign-in gate as any other edit.

Zero is an invitation, not an absence

A badge with 0 endorsements, an unfilled contact field, an empty gallery — none of these hide the slot. Each renders in its dashed/faint/italic "not yet" state with a direct call to fill it, applied consistently across labs, film stock, and photos.

Do / don't

Do

  • Drive selection/active state through the shared data-on/data-tabon attributes rather than one-off active classes
  • Give --sunk to anything that's a placeholder for real content, never to a real content surface
  • Keep grid-cell inputs (pricing, hours) visually lighter than standalone fields — density should read in the border weight
  • Reuse the hatch placeholder for lab photography and the duotone placeholder for film photography — never swap them

Don't

  • Add a third placeholder texture — hatch and duotone already carry the labs-vs-films distinction; a new one dilutes it
  • Let the prototype's own device-frame chrome (#EFEEEB mat, Mobile/Desktop/Reset bar) leak into a spec as if it were product UI
  • Fill a status pill with a process or signal color — status stays achromatic, always
  • Treat the swappable --signal prop as supported theming — it's a design-review tool, ship default red only
