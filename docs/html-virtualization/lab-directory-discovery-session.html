This page rolls up every requirements decision made across all four MVP feature areas — including a mid-session architecture pivot on the portfolio feature — into one record.

A.Lab Directory & Discovery12 decisions · full write-up: prd/lab-directory-discovery.md

Decided

Single persona — the community member. No Lab Owner or Moderator/Admin persona in MVP. Browsing needs no account; contributing (add/edit a lab, mark closed, upload atmosphere photos) requires login, and every contribution is attributed.

Decided

Trust-by-default. Edits go live immediately, no review queue. Trust is maintained after the fact via attribution and full edit history, not gatekeeping up front. This precedent carries through every other feature below.

Decided

Minimum to publish a lab: name + location + at least one chemical process. Everything else (pricing, hours, scanner, inventory, photos) is optional and fills in later via community edits.

Decided

Two distinct photo concepts: Lab Atmosphere Photos (storefront/interior, attached to the Lab, no quality judgment) vs. Film Sample Photos (scan quality, attached only to the Film Stock — never the Lab, protecting a lab's reputation from a subjectively "bad" scan). This split becomes the product's core content-integrity rule.

Decided

No automated duplicate detection. Soft prevention — nearby existing labs surface on the map during the add-lab flow. Manual cleanup only if a duplicate slips through.

Decided

Inventory scoped down: "what do they sell," not live stock. Film stock sold must link to a real Film Stock catalog entry (powers reverse search); darkroom equipment/chemicals use loose tags with no catalog link. No quantity tracking, no "Last Verified" mechanic.

Decided

Lab status has three independent signals: weekly hours (auto-computes open/closed), a manual status override for exceptions, and a permanent "Mark as Closed" flag (hidden from search, still viewable via direct link). All trust-by-default.

Decided

Discovery auto-locates the user by default; manual location search is a first-class alternative. Results rank nearest-first, weighted toward more complete data. Thai and English both required.

Decided

Empty states double as contribution on-ramps: zero labs nearby → add the first lab; zero labs after filtering → edit a nearby lab to add the missing process, not create a duplicate entry.

B.Film Stock Index & Gallery3 decisions · full write-up: prd/film-stock-index-gallery.md

Decided

Catalog uses the same trust-by-default model as Labs — any logged-in user can add/edit a film stock entry, live immediately, full edit history, soft duplicate prevention (no hard block). Keeps the Lab Directory's Inventory→Film Stock linkage from becoming a launch blocker.

Decided

One catalog entry per film name + ISO — format (135/120) is a multi-select attribute, not a separate entry. The emulsion is identical across formats; splitting would fragment the inspiration gallery and double catalog maintenance for no matching benefit.

Decided

The Gallery has no upload flow of its own — it's a derived view of any Photo tagged with that Film Stock (see feature D's Photo entity). Scanner model may show as neutral metadata; the specific Lab never does. Accepted MVP risk: a stock can show zero gallery photos until someone tags one.

D.Minimal Photobook Portfolio8 decisions · full write-up: prd/photobook-portfolio.md

Architecture pivot

Mid-session, the rigid Lab → Roll → Photo hierarchy was replaced with an Are.na-inspired model: Photo is now an atomic entity (owns its own Film Stock/Scanner/Camera/Chemistry metadata) that can belong to many Photobooks — thematic, concept-driven collections, public by default. Connection lets any user save another user's public Photo into their own Photobook without re-uploading it. "Roll" is retired as a curation-unit term. This single change simplified feature B's dependency (the Gallery only needs the Photo entity, not Photobook mechanics) and drove every decision below.

Decided

Content-integrity rule reaffirmed. The pivot's original "Reverse Attribution" pitch (click a photo, see the exact Lab used) directly conflicted with the locked no-lab-attribution rule from feature A — the same link that lets a good scan reflect well on a lab lets a bad one reflect badly. Resolved: Scanner model stays as neutral metadata, same category as Camera; the specific Lab is never shown or linkable from a Photo, individually or in aggregate.

Decided

Connections use a reference model, not copies — one canonical Photo object per upload; every Photobook that Connects it points to the same object. Editing the original updates everywhere; deleting it removes it everywhere it was Connected.

Decided

Photos are instant-live — no draft/private state, no separate publish step. Matches the trust-by-default precedent and actual Are.na block behavior; curation happens at the Photobook level, which is already public by default.

Decided

The per-user photo cap applies only to original uploads, not to Connections (which cost zero extra storage as references). Capping total Photos including Connections would directly fight the network-effect goal the pivot is built around.

Decided

No restriction on Connecting for MVP — any public Photo can be freely saved into any Photobook. An uploader's only recourse is deleting their own Photo outright. Matches Are.na's real precedent; easier to add restriction later than retrofit openness.

Decided

One artist's note per Photobook (2-3 lines), not per individual Photo. Matches the original brief and protects the "high negative space, no clutter" visual direction as Photobooks grow via free Connecting.

Decided

When a Connected Photo's source is deleted, its slot is removed silently and the grid re-flows — no "removed by uploader" placeholder. (Flagged for revisit if deliberate photo-essay sequencing turns out to matter more than a clean, always-intentional-looking grid.)

C.Community & Data Integrity — Upvote/Badges3 decisions · full write-up: prd/community-data-integrity.md

Decided

Fixed, curated badge list (e.g. "Fast Turnaround," "Clean Scan") — not freeform/user-proposed tags. With no Moderator/Admin persona in MVP, an open namespace has no way to consolidate duplicate/synonym badges; a fixed list keeps every badge comparable across labs.

Decided

Votes are a retractable toggle — one (user, lab, badge) state, on or off, changeable any time. A badge's strength always reflects current sentiment, not a historical total. This also inherently enforces one vote per user per badge.

Decided

No minimum vote threshold to display a badge — it shows at 1 endorsement, always paired with its current count, so users judge credibility themselves rather than the product gatekeeping behind an untuned constant.

Vocabulary, current stateCONTEXT.md, as of this session

Photo
The atomic unit of community-uploaded visual content. Carries Film Stock, Scanner model, Camera, Chemistry metadata — never a specific Lab. Can belong to multiple Photobooks.
Photobook
A thematic, concept-driven collection of Photos curated by a user, public by default. The unit of curation on a portfolio (/u/@username). Replaces "Roll."
Connection
Saving another user's public Photo into one's own Photobook without re-uploading — a reference to the same canonical Photo, not a copy.
Lab Atmosphere Photo
A community-uploaded photo of a lab's storefront/interior, attached directly to the Lab. Venue documentation only.
Avoid: conflating with Film Sample Photo
Film Sample Photo
A community-uploaded Photo showing what a film stock looks like when processed/scanned, surfaced on that stock's Gallery. Attached only to the Film Stock, never a Lab.
Avoid: "Lab photo" or "sample photo" without specifying which it's linked to
Roll (retired as curation unit)
Formerly the fixed unit of curation on a portfolio. Replaced by Photobook + atomic Photo so a photo isn't locked to one rigid group. May still appear in copy to mean a physical roll of film.
