Photobook Portfolio — prototype gap plan

Frames 1j · 1k · 1l — grains-wireframe.html vs grains-prototype.html vs docs/prd/photobook-portfolio.md · rev. 2, after adversarial review

The wireframe covers the photobook feature area in three frames: 1j public profile, 1k photobook detail, 1l photo detail. The prototype implements all three as screens (portfolio, book, photo) and self-references those frame IDs in its own wireMap, so the intended mapping is explicit.

One qualifier on that mapping: the prototype's photo screen is doing double duty. Its eyebrow reads SAMPLE SCAN, its <h1> is the film stock name and its CTA is "See the stock" — it is really frame 1g's film-stock gallery photo, wearing 1l's route. Several findings below are therefore not "1l built badly" but "1l never built, because one screen is serving two roles." The fix is to split them.

Broadly: the prototype has the shells of all three screens and honours the content-integrity rule, but it is missing every state variant (visitor vs. owner, empty, connected vs. own), the artist's note, any Photo upload path, the Connect destination sheet, and the profile-as-destination routing the PRD's only discovery path depends on. In two places it contradicts a resolved PRD decision outright.

What the prototype gets right

  • Content-integrity rule (PRD §2) is honoured — no Lab row on the photo, no "where was this developed" affordance, and an explicit line that scanner model is neutral technical metadata in the same class as camera. This is the highest-risk rule in the feature and it holds.
  • Logged-out Connect is handled correctly — gated behind auth() with the button still visible and the image and metadata never requiring an account, exactly as the wireframe specifies. Listed here so it doesn't get "fixed" into a hidden button.
  • No likes, no followers, no feed — consistent with PRD §9 and the "no ads, no like counts" positioning.
  • Instant-live photos (PRD §4) — no draft state anywhere.
  • Reference-not-copy language — "a photobook is a reading order, not a copy" states PRD §3 in product voice.
  • Frame-ID traceability — wireMap already links each screen to its wireframe frame, so regressions are checkable.
Cross-cutting, outside 1j–1l: both files use border-radius throughout (116 occurrences in the prototype, 169 in the wireframe) and the prototype's paper is #FDFDFC, while CLAUDE.md's locked design direction says sharp flat rectangles only, no rounded corners, warm paper #F9F8F6. Since wireframe and prototype both diverge, this is a design-direction decision to reconfirm or amend in CLAUDE.md — not a prototype bug. Separately, wireframe frame 2b (Accounts) offers LINE / Google / Apple / email sign-in while CLAUDE.md and the prototype are Google-only — a community-PRD question, out of scope here. Note the wireframe's own 1l annotation misreferences that frame as "1h" (which is Suggest Lab / Suggest Edit); worth correcting in the wireframe.

Plan

Phase 0 — Decisions · CLOSED 2026-09-04

Recorded as PRD decisions 10–12 · nothing here blocks Phase 1
  1. Upload surface (J10, J11) → RESOLVED, PRD §10. Upload starts from the owner's profile ("+ Upload") and from inside a Photobook they own. Closes a requirement film-stock PRD §3 had delegated to feature D and feature D never picked up. Sub-question still open: where a Photo in no Photobook surfaces on the profile (J11).
  2. Reuse counters (J4, L2) → RESOLVED, PRD §11. "Also appears in · N Photobooks" ships (a fact about the Photo, and the only demonstration of the reference model); "Connected by others" does not (a popularity score on a person). L2 is therefore un-gated — build it, from seeded cross-user data.
  3. Self-Connection (L3) → defaulted no — own Photo shows Edit / Delete instead. PRD §12.
  4. Photobook visibility (K8) → defaulted no non-public state — drop the "public" label. PRD §12.
  5. Format on a Photo (L5) → defaulted yes, on film-stock PRD §2's authority. PRD §12.
  6. Artist's note placement (J5) → defaulted to the wireframe's markup over its annotation: on profile cards everywhere except the mobile grid. PRD §12.
  7. Not blocking: the cap's numeric value — PRD §5 rules it out of scope. 50 as placeholder data.
  8. Not open: whether the artist's note ships. PRD §7 is resolved; only placement was live.

Items 3–6 were defaulted, not explicitly chosen — recorded as PRD §12 PROPOSED so they stay visible and cheap to overturn.

Phase 1 — Data model

Prototype edits · everything downstream depends on this

PRD follow-ups this exposed

Five of these were closed on 2026-09-04 as PRD decisions 10–12 (see Phase 0). What remains open:

  • Where a book-less Photo surfaces on the profile (J11) — PRD §10 resolved the upload surface but explicitly left this sub-question open. The profile lists Photobooks only, so a Photo in no Photobook is reachable from the Film Stock Gallery but not from its own author's page.
  • Also update film-stock PRD §3 — its "still open" note about upload now has two answers: visibility from §4, surface from §10. Worth closing the loop there so the two PRDs don't drift.
  • §8 silent removal has no UI anywhere by design — the wireframe flags it as the one resolved decision with nothing to show. Worth a line in the PRD noting that absence is the implementation.
  • Book-level ownership — the PRD never says whether a Photobook made entirely of Connections (the wireframe's "Borrowed Light", 18 photos / 18 connected) is a first-class case. It follows from §5 but isn't stated.
