Eight reported app bugs

Branch claude/app-bugs-improvements-9651cf · 2026-09-11

Eight issues reported from using the running app. They are not one theme: two are genuine missing features — there is no delete path for a lab atmosphere photo, and no way at all to put your own photo into your own photobook — three are UI built to show a number where it should show the thing, one is a routing decision, one is a colour, and one is a question about geolocation that the UI should have answered by itself.

1 · The language toggle needs a page reload

Cause. components/layout/lang-toggle.tsx:32 renders <Link href="?lang=th">. proxy.ts:28 turns that into a cookie and a redirect, but <Link> does a soft navigation: the root layout is the only thing that calls currentLang() (app/layout.tsx:52), and a shared layout is not re-rendered when you navigate to the same route. <html lang> is written once per document and cannot change without a document load either.

A second, quieter bug rides along: a ?-only href replaces the whole query string, so switching language on /labs?lat=…&process=c41 lands on bare /labs and throws the search away. tests/i18n.test.ts:99 believes this is covered, but it only tests proxy() against a hand-built URL — the proxy preserves params; the link never supplies them.

  • Add a pure langHref(pathname, search, lang) to lib/i18n.ts.
  • Make lang-toggle.tsx a client component using usePathname() + useSearchParams(), rendering plain <a> elements — a real document navigation is what makes the cookie take effect immediately, and it removes the prefetch hazard.
  • Wrap the toggle in <Suspense> in site-header.tsx:35.
  • Extend tests/i18n.test.ts to cover langHref — the assertion the existing test thought it was making.

3 · Does “Use my location” ask for location?

Yes — components/labs/location-prompt.tsx:30 calls navigator.geolocation.getCurrentPosition, which triggers the browser permission prompt and only works in a secure context. That the user could not tell is the actual defect: the button says nothing about what it will do, and every failure — denied, unavailable, timed out, insecure page — collapses into one sentence.

  • A line under the button saying it uses the browser's location and will ask.
  • Branch on GeolocationPositionError.code, and check window.isSecureContext up front.
  • Same treatment for components/films/nearby-labs.tsx:66, which lacks even the "geolocation" in navigator guard.

4 · Lab edit: photos invisible, no preview, Save disabled

Three things in one component, components/lab-form/atmosphere-photos.tsx.

  • Existing photos never render. lab-form.tsx:563 passes only a count; the rows are already loaded by getLab. Pass the rows, resolve them with publicUrl in the edit page, render thumbnails.
  • No remove control anywhere in the codebase. Add deleteLabPhotoRow (lib/queries/photos.ts) and a deleteLabPhoto action that also calls deleteObject, then revalidates both lab paths.
  • No preview. The object URL at lines 46–49 is created to measure and revoked without ever being shown. Hold it in state — the Picked pattern in photo-uploader.tsx:43-49.
  • “Cannot save with only the image changed.” Photos are outside LabDraft, so canSave stays false under “Nothing changed yet.” Nothing is lost — the upload commits at select time — but the form says the opposite. Have the photo section report its own outcome; leave the diff gate alone.
  • Add the client-side checkUpload pre-flight the community uploader has.

6 · Cannot add your own photos to your own photobook

Cause. The feature was never built. appendPhotobookItem exists and its own doc says filing your own photo is ordinary curation — but its only caller is the upload path. The one “add” action the UI can reach routes to connectPhoto, which hard-refuses your own photo. The photobook page never calls currentUser(), and the photo page deliberately skips fetching connect targets for the owner. Every route out is closed. docs/prd/photobook-portfolio.md:90 asks for exactly this affordance.

  • lib/queries/books.ts — addOwnPhoto(tx, photobookId, photoId, ownerId), a sibling of connectPhoto rather than a flag on it.
  • lib/queries/photos.ts — listOwnPhotosForBook(ownerId, photobookId) with an inBook flag.
  • app/u/actions.ts — fileIntoPhotobook; removeFromPhotobook already un-files.
  • Surface A — make the photobook page owner-aware and add components/books/add-to-book.tsx, a picker with ticks; give the empty state this action instead of a dead sentence.
  • Surface B — on the photo page, an owner gets a “File into photobook” sheet beside Edit/Delete, reusing ConnectSheet. Correct the doc comment at photo-owner-actions.tsx:14, which states the opposite.

7 · “+ Add a sample” on the film stock page

It links to your own profile root — no anchor, so you land above an UPLOAD section that is the last block on the page, and no stock id, so the stock you came from is not preselected. Remove the link and rewrite deviation note 2 in the file's doc comment to record that the affordance was removed rather than relocated.

8 · “Upload photograph” is red

It is not the destructive token. .grains-save paints with --primary, the signal red the design system calls “the one action color” — the stylesheet even carries a comment about the two having been separated precisely so this button and the failure banner stop matching. Per the decision taken, change only this button.

  • Give the uploader's button its own class in photo-uploader.css with the ink/outline treatment .grains-action uses.
  • Check .grains-upload-drop in the same pass so the drop zone and the commit button do not disagree.

Accepted trade: the lab form's “Save — goes live now” stays signal red while the uploader's commit button is ink. That is the cost of not touching the palette from a feature branch (CLAUDE.md P7).
